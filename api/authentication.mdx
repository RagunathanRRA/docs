## Overview

The Samudra API uses **API key authentication**. Every request must include a valid API key in the `Authorization` header. There are no session tokens or OAuth flows — your API key is a long-lived credential that you include on each call.

## Generating an API Key

1. Log in to the [Samudra dashboard](https://app.samudra.io).
2. Navigate to **Organization Settings** in the sidebar.
3. Select the **API Keys** tab.
4. Click **Generate New Key**.
5. Give the key a descriptive name (e.g., `production-integration` or `read-only-monitoring`).
6. Choose the key scope: **Read-only** or **Full access** (see [Key Scopes](#key-scopes) below).
7. Click **Create Key** and copy the key immediately — it will not be shown again.

<Warning>
  API keys are displayed only once at the time of creation. If you lose a key, you must revoke it and generate a new one.
</Warning>

## Using Your API Key

Pass your API key as a Bearer token in the `Authorization` header on every request:

```
Authorization: Bearer <your-api-key>
```

### Example Request

```bash
curl https://api.samudra.io/v1/pumps \
  -H "Authorization: Bearer sk_live_your_api_key_here"
```

## Key Scopes

Samudra issues two types of API keys, distinguished by their prefix:

| Prefix | Scope | Permitted Actions |
|---|---|---|
| `sk_ro_` | **Read-only** | `GET` requests only — list pumps, read metrics, view alerts |
| `sk_live_` | **Full access** | All operations, including pump control and acknowledging alerts |

Use read-only keys wherever write access is not required. This limits the blast radius if a key is ever exposed.

## Security Best Practices

- **Treat API keys like passwords.** Anyone who holds a key has the same access level as the key's scope allows.
- **Never commit keys to source control.** Use environment variables or a secrets manager (e.g., AWS Secrets Manager, HashiCorp Vault) to inject keys at runtime.
- **Use one key per integration.** This makes it straightforward to audit usage and revoke a specific key without disrupting other services.
- **Rotate keys periodically.** Generate a new key, update your integration, then revoke the old one.

```bash
# Recommended: load your key from an environment variable
export SAMUDRA_API_KEY="sk_live_your_api_key_here"

curl https://api.samudra.io/v1/pumps \
  -H "Authorization: Bearer $SAMUDRA_API_KEY"
```

## Revoking a Key

To revoke an API key:

1. Go to **Organization Settings → API Keys** in the dashboard.
2. Find the key you want to revoke and click the **Revoke** button next to it.
3. Confirm the revocation in the dialog.

Revoked keys stop working immediately. Any in-flight requests using the revoked key will be rejected with a `401 Unauthorized` response.

## Authentication Error Responses

| HTTP Status | Error Code | Cause |
|---|---|---|
| `401 Unauthorized` | `missing_api_key` | No `Authorization` header was provided |
| `401 Unauthorized` | `invalid_api_key` | The key is malformed, expired, or has been revoked |
| `403 Forbidden` | `insufficient_permissions` | The key's scope does not permit this action (e.g., a read-only key attempting a control command) |

**Example 401 response:**

```json
{
  "error": {
    "code": "invalid_api_key",
    "message": "The API key provided is invalid or has been revoked.",
    "request_id": "req_abc456"
  }
}
```

**Example 403 response:**

```json
{
  "error": {
    "code": "insufficient_permissions",
    "message": "This API key does not have permission to perform control actions. Use a full-access key.",
    "request_id": "req_def789"
  }
}
```
