## Overview

The Alerts API gives you programmatic access to the alerts generated by Samudra's monitoring engine. Alerts are triggered when a pump's sensor readings cross a configured threshold — for example, if pressure exceeds a safety limit or temperature climbs above a warning level. You can list, filter, and acknowledge alerts through this API to build custom notification workflows, incident management integrations, or operational dashboards.

## The Alert Object

<ResponseField name="id" type="string">
  Unique identifier for the alert, prefixed with `alert_`. Example: `alert_gh3421`.
</ResponseField>

<ResponseField name="pump_id" type="string">
  ID of the pump that triggered this alert.
</ResponseField>

<ResponseField name="pump_name" type="string">
  Display name of the pump at the time the alert was triggered.
</ResponseField>

<ResponseField name="metric" type="string">
  The sensor metric that exceeded its threshold. One of `flow_rate`, `pressure`, `temperature`, or `runtime_seconds`.
</ResponseField>

<ResponseField name="value" type="number">
  The actual sensor reading that triggered the alert.
</ResponseField>

<ResponseField name="unit" type="string">
  The unit of measurement for the `value` and `threshold` fields (e.g., `bar`, `L/min`, `°C`).
</ResponseField>

<ResponseField name="threshold" type="number">
  The configured threshold value that was breached to generate this alert.
</ResponseField>

<ResponseField name="severity" type="string">
  Severity level of the alert. One of `info`, `warning`, or `critical`.
</ResponseField>

<ResponseField name="status" type="string">
  Current status of the alert. One of `active`, `acknowledged`, or `resolved`.
</ResponseField>

<ResponseField name="triggered_at" type="string">
  ISO 8601 timestamp of when the alert condition was first detected.
</ResponseField>

<ResponseField name="acknowledged_at" type="string">
  ISO 8601 timestamp of when the alert was acknowledged. `null` if not yet acknowledged.
</ResponseField>

<ResponseField name="acknowledged_by" type="string">
  Email address of the user or identifier of the API key that acknowledged the alert. `null` if not yet acknowledged.
</ResponseField>

## List Alerts

Returns a filtered, paginated list of alerts across your organization.

```
GET /v1/alerts
```

### Query Parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| `pump_id` | string | No | Filter alerts to a specific pump (e.g., `pump_abc123`). |
| `status` | string | No | Filter by alert status. One of `active`, `acknowledged`, or `resolved`. |
| `severity` | string | No | Filter by severity level. One of `info`, `warning`, or `critical`. |
| `from` | string | No | Return only alerts triggered at or after this ISO 8601 timestamp. |
| `to` | string | No | Return only alerts triggered at or before this ISO 8601 timestamp. |
| `limit` | integer | No | Number of results per page. Default: `20`. Maximum: `100`. |
| `offset` | integer | No | Number of results to skip for pagination. Default: `0`. |

### Example Request

```bash
curl "https://api.samudra.io/v1/alerts?status=active&severity=critical&limit=5" \
  -H "Authorization: Bearer sk_live_your_api_key_here"
```

### Example Response

```json
{
  "data": [
    {
      "id": "alert_gh3421",
      "pump_id": "pump_abc123",
      "pump_name": "Main Intake Pump 1",
      "metric": "pressure",
      "value": 6.45,
      "unit": "bar",
      "threshold": 6.00,
      "severity": "critical",
      "status": "active",
      "triggered_at": "2024-03-15T13:58:42Z",
      "acknowledged_at": null,
      "acknowledged_by": null
    }
  ],
  "meta": {
    "total": 3,
    "limit": 5,
    "offset": 0
  }
}
```

## Acknowledge an Alert

Marks an alert as acknowledged, indicating that a member of your team has reviewed it. Acknowledging an alert does not resolve it — the alert will move to `resolved` status automatically once the underlying sensor readings return to within acceptable thresholds.

```
POST /v1/alerts/{id}/acknowledge
```

### Path Parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| `id` | string | Yes | The unique alert ID (e.g., `alert_gh3421`). |

### Request Body

The request body is optional. If provided, it must be valid JSON.

```json
{
  "note": "Investigated, within acceptable range for current operating conditions."
}
```

| Field | Type | Required | Description |
|---|---|---|---|
| `note` | string | No | A free-text note from the operator describing their investigation or action taken. Stored on the alert record for audit purposes. |

### Example Request

```bash
curl -X POST https://api.samudra.io/v1/alerts/alert_gh3421/acknowledge \
  -H "Authorization: Bearer sk_live_your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{"note": "Pressure spike during startup sequence — monitoring. No action required."}'
```

### Example Response

```json
{
  "id": "alert_gh3421",
  "pump_id": "pump_abc123",
  "pump_name": "Main Intake Pump 1",
  "metric": "pressure",
  "value": 6.45,
  "unit": "bar",
  "threshold": 6.00,
  "severity": "critical",
  "status": "acknowledged",
  "triggered_at": "2024-03-15T13:58:42Z",
  "acknowledged_at": "2024-03-15T14:05:30Z",
  "acknowledged_by": "operator@example.com",
  "note": "Pressure spike during startup sequence — monitoring. No action required."
}
```

The response is the full updated alert object with `status` set to `acknowledged` and `acknowledged_at` / `acknowledged_by` populated.

### Error Responses

| HTTP Status | Error Code | Description |
|---|---|---|
| `403 Forbidden` | `insufficient_permissions` | The API key does not have permission to acknowledge alerts. |
| `404 Not Found` | `alert_not_found` | No alert with the given ID exists in your organization. |
| `409 Conflict` | `already_acknowledged` | The alert has already been acknowledged. |
